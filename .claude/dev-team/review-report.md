Everything else resolves out of `pg_catalog`, which stays implicitly searched at `search_path = ''`: `now`, `date_trunc`, `make_interval(months =>)`, `to_char`, `format`, `hashtext`, `pg_advisory_xact_lock`, `array_length`, `array_append`, `lower`, `trim`, `coalesce`, `nullif`, `current_setting`; operators `=`/`is distinct from` on `data.client_status` (`enum_eq(anyenum,anyenum)`), `!~` (`textregexne`), `->>` on jsonb, `= any` on text[]; casts `::date`, `::jsonb`, `::uuid`, `::data.member_role`; `AT TIME ZONE` (parser emits `pg_catalog.timezone` via `SystemFuncName`, not a path lookup). No `regclass`/`regproc` literal, no `to_regclass`, no extension function, type or operator in any body. `gen_random_uuid()` and the gin index appear only in column defaults and index definitions on other tables, which resolve at DDL time.
- **`ensure_raw_partitions` dynamic SQL (lines 55-59).** All four `execute format` strings are `data.%I`-qualified; the partition bound `%L` literals coerce against the parent's `timestamptz` key by OID; copied defaults (`now()`) and enum columns (`data.source`) are stored parse nodes and OIDs, not names; `anon`/`authenticated` are role names, not path-resolved.
- **Q2 signature preservation, all nine.** Bodies are byte-identical to the originals. Language, volatility (`stable`×3, `immutable`×1, implicit `volatile`×5), return type, argument names (`ts`, `client`, `tags`) and defaults (none) all match; none was `strict` before or now; all nine were and remain `security invoker`; `set search_path = ''` is the only added clause. Named-argument callers such as `data.local_day(ts => …)` still bind.
- **Q3 triggers.** None of the four trigger functions touches `tg_argv`, `tg_name` or `tg_table_name`; `new.`/`old.` fields resolve from the trigger tuple descriptor, never the path. The migration contains no `create trigger` or `drop`, so all 14 `touch` triggers plus the three `data.clients` triggers keep their `pg_trigger.tgfoid` bindings; `create or replace` preserves the OID and the ACLs the `revoke`/`grant` block in `20260912000200_access.sql` set.
- **Q4 SQL inlining.** Correct that `SET search_path` makes `jwt_client_id`/`jwt_client_role` non-inlinable (`inline_function()` bails on non-null `proconfig`). It costs nothing here: `jwt_client_role` has no callers, and `jwt_client_id` is called only from inside `data.active_client_id`/`active_client_role`, which are already non-inlinable (`security definer` + `set`) and are wrapped as `(select …)` InitPlans in all 15 policies — so it runs once per query, not once per row. Plan shape is unchanged: the qual `m.client_id = data.jwt_client_id()` was a stable expression inlined and is a stable expression now, still usable as an index key. **Recommendation: keep the pin as written.** Tradeoff line 1: the alternative (schema-qualified body, no `set`) does not satisfy lint 0011, which reads `proconfig` and not the body, and would fail the new `function_search_path_pinned` test. Tradeoff line 2: the pin's real cost is one GUC save/restore per query in an InitPlan, which is not measurable — and do not add `security definer` to these two, since they only read a request GUC and definer would widen blast radius for no gain.

No `security invoker` filter. Covers all 30 functions (16 `data`, 14 `api`); all 14 `api.*` RPCs and the four RLS helpers were already pinned, confirming nine was the right count.
- **Q6 push safety.** No lock hazard: `create or replace function` takes AccessExclusive on the `pg_proc` object alone, and executing a function takes no lock on it, so concurrent inserts on `data.clients` firing `touch_updated_at` and `clients_timezone_valid` will not block. Nine fast DDLs in one CLI transaction. No dependency ordering issue — every function is replaced in place, so no dependent trigger, policy, view or RPC is invalidated and nothing needs a specific order. A worker mid-`ensure_raw_partitions` holds `pg_advisory_xact_lock` and a lock on `data.raw`; the migration touches neither, so no deadlock, and the in-flight call finishes on the old body.
